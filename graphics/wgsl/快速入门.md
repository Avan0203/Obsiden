# 📘 WGSL 基础

## 🔢 基本类型

WGSL 中包括这些基本类型：

| 类型 | 说明 |
|------|------|
| `i32` | 32 位有符号整数 |
| `u32` | 32 位无符号整数 |
| `f32` | 32 位浮点数 |
| `bool` | 布尔值 |
| `f16` | 16 位浮点数（可选特性，使用前请检查并请求） |

## 📝 变量声明

在 JavaScript 中，可以像这样声明变量和函数：

```js
var a = 1;
let c = 3;
function d(e) { return e * 2; }
```

在 WGSL 中，这些声明的完整形式是：

```wgsl
var a: f32 = 1;
let c: f32 = 3;
fn d(e: f32) -> f32 { return e * 2; }
```

需要注意：

- 变量声明中添加了 `: <类型>`，例如 `: f32`
- 函数声明中添加了 `-> <类型>`

## 🪄 自动类型

WGSL 为变量提供了快捷方式。类似于 TypeScript，如果没有声明变量的类型，则它将自动成为右侧表达式的类型。

```wgsl
fn foo() -> bool { return false; }

var a = 1;      // a 是 i32 类型
let b = 2.0;    // b 是 f32 类型
var c = 3u;     // c 是 u32 类型
var d = foo();  // d 是 bool 类型
```

## 🔄 类型转换

严格的类型意味着经常需要转换类型。

```wgsl
let a = 1;      // a 是 i32 类型
let b = 2.0;    // b 是 f32 类型
let c = a + b;  // 错误：不能将一个 i32 的值添加到 f32 的值上
```

为了修复该错误，将其中一个变量的类型转换为另一个的类型：

```wgsl
let a = 1;           // a 是 i32 类型
let b = 2.0;         // b 是 f32 类型
let c = f32(a) + b;  // 这样就行了
```

但是！WGSL 有所谓的 **抽象整数（AbstractInt）** 和 **抽象浮点数（AbstractFloat）**。可以把它们视为尚未决定类型的数字。这些都是仅在编译时有效的特性。

```wgsl
let a = 1;       // a 是 i32 类型
let b = 2.0;     // b 是 f32 类型
let c = a + b;   // 错误：不能将一个 i32 的值添加到 f32 的值上
let d = 1 + 2.0; // d 是 f32 类型
```

| 字面量 | 类型 |
|--------|------|
| `2i` | `i32` |
| `3u` | `u32` |
| `4f` | `f32` |

## 📦 `var` / `let` / `const`

`var`、`let` 和 `const` 在 WGSL 和 JavaScript 中的含义不同。

### JavaScript

| 关键字 | 作用域 | 可变性 |
|--------|--------|--------|
| `var` | 函数作用域 | 可变 |
| `let` | 块作用域 | 可变 |
| `const` | 块作用域 | 不可变（常量变量） |

### WGSL

所有变量都具有**块作用域**。

| 关键字 | 含义 |
|--------|------|
| `var` | 具有存储空间的变量，因此是**可变的** |
| `let` | 常量值（运行时不可再赋值） |
| `const` | 编译时常量，不能用于运行时值 |

```wgsl
fn foo() {
  let a = 1;
  a = a + 1; // 错误：a 是常量表达式
  var b = 2;
  b = b + 1; // 可以
}
```

`const` 不是变量，而是编译时常量：

```wgsl
const one = 1;                 // 可以
const two = one * 2;           // 很好
const PI = radians(180.0);     // 没问题

fn add(a: f32, b: f32) -> f32 {
  const result = a + b; // 错误！const 只能用于编译时表达式
  return result;
}
```

## 📐 向量类型

WGSL 有三种向量类型：`vec2`、`vec3`、`vec4`。基本样式是 `vec?<type>`。

| 写法 | 含义 |
|------|------|
| `vec2<i32>` | 两个 `i32` 的向量 |
| `vec3<f32>` | 三个 `f32` 的向量 |
| `vec4<u32>` | 四个 `u32` 的向量 |
| `vec3<bool>` | 三个布尔值的向量 |

示例：

```wgsl
let a = vec2<i32>(1, -2);
let b = vec3<f32>(3.4, 5.6, 7.8);
let c = vec4<u32>(9, 10, 11, 12);
```

### 选择器（accessors）

可以使用各种选择器访问向量内的值：

```wgsl
let a = vec4<f32>(1, 2, 3, 4);
let b = a.z;   // 通过 x, y, z, w 访问
let c = a.b;   // 通过 r, g, b, a 访问
let d = a[2];  // 通过数组元素选择器访问
```

上面例子中，`b`、`c` 和 `d` 都相同，都在访问 `a` 的第三个元素，值都是 `3`。

### 调制（swizzle）

也可以同时访问多个元素：

```wgsl
let a = vec4<f32>(1, 2, 3, 4);
let b = a.zx;                     // 通过 x, y, z, w 访问
let c = a.br;                     // 通过 r, g, b, a 访问
let d = vec2<f32>(a[2], a[0]);
```

上面例子中，`b`、`c` 和 `d` 都相同，都是 `vec2<f32>(3, 1)`。

还可以重复元素：

```wgsl
let a = vec4<f32>(1, 2, 3, 4);
let b = vec3<f32>(a.z, a.z, a.y);
let c = a.zzy;
```

上面例子中，`b` 和 `c` 一样，都是 `vec3<f32>`，内容是 `3, 3, 2`。

### 向量快捷方式

基本类型有快捷方式：

| 完整写法 | 快捷写法 |
|----------|----------|
| `<i32>` | `i` |
| `<f32>` | `f` |
| `<u32>` | `u` |
| `<f16>` | `h` |

```wgsl
let a = vec4<f32>(1, 2, 3, 4);
let b = vec4f(1, 2, 3, 4);
```

`a` 和 `b` 是相同的类型。

### 向量构造

可以用更小的类型构建向量：

```wgsl
let a = vec4f(1, 2, 3, 4);
let b = vec2f(2, 3);
let c = vec4f(1, b, 4);
let d = vec4f(1, a.yz, 4);
let e = vec4f(a.xyz, 4);
let f = vec4f(1, a.yzw);
```

`a`、`c`、`d`、`e` 和 `f` 是相同的。

### 向量数学

可以在向量上进行数学运算：

```wgsl
let a = vec4f(1, 2, 3, 4);
let b = vec4f(5, 6, 7, 8);
let c = a + b; // c 是 vec4f(6, 8, 10, 12)
let d = a * b; // d 是 vec4f(5, 12, 21, 32)
let e = a - b; // e 是 vec4f(-4, -4, -4, -4)
```

许多函数也适用于向量：

```wgsl
let a = vec4f(1, 2, 3, 4);
let b = vec4f(5, 6, 7, 8);
let c = mix(a, b, 0.5);                    // c is vec4f(3, 4, 5, 6)
let d = mix(a, b, vec4f(0, 0.5, 0.5, 1));  // d is vec4f(1, 4, 5, 8)
```

## 🧮 矩阵

WGSL 有许多矩阵类型。矩阵是向量的数组，格式是 `mat<向量数量>x<向量大小><类型>`。

例如：`mat3x4<f32>` 是一个包含 3 个 `vec4<f32>` 的数组。

就像向量一样，矩阵也有快捷方式：

```wgsl
let a: mat4x4<f32> = ...;
let b: mat4x4f = ...;
```

`a` 和 `b` 是相同的类型。

### 矩阵向量访问

可以使用数组语法引用矩阵中的向量：

```wgsl
let a = mat4x4f(...);
let b = a[2]; // b 是 a 中第 3 个向量的一个 vec4f
```

最常用的 3D 计算矩阵类型是 `mat4x4f`，可以直接与 `vec4f` 相乘产生另一个 `vec4f`：

```wgsl
let a = mat4x4f(....);
let b = vec4f(1, 2, 3, 4);
let c = a * b; // c 是一个 vec4f，是 a * b 的结果
```

## 📚 数组

WGSL 中的数组使用 `array<type, numElements>` 语法声明：

```wgsl
let a = array<f32, 5>;     // 一个包含五个 f32 的数组
let b = array<vec4f, 6>;   // 一个包含六个 vec4f 的数组
```

也有 `array` 构造函数。它可以接受任意数量的参数，并返回一个数组。参数必须全部是相同类型：

```wgsl
let arrOf3Vec3fsA = array(vec3f(1,2,3), vec3f(4,5,6), vec3f(7,8,9));
let arrOf3Vec3fsB = array<vec3f, 3>(vec3f(1,2,3), vec3f(4,5,6), vec3f(7,8,9));
```

上面例子中，`arrOf3Vec3fsA` 和 `arrOf3Vec3fsB` 是相同的类型。

> 在 WGSL 版本 1 中，没有方法获取固定大小数组的大小。

### 运行时大小数组

只有根作用域存储声明，或作为根作用域结构体最后一个字段的数组，才能指定为没有大小。

```wgsl
struct Stuff {
  color: vec4f,
  size: f32,
  verts: array<vec3f>,
};

@group(0) @binding(0) var<storage> foo: array<mat4x4f>;
@group(0) @binding(1) var<storage> bar: Stuff;
```

`foo` 和 `bar.verts` 中的元素数量由运行时使用的绑定组设置定义。可以在 WGSL 中使用 `arrayLength` 查询此大小：

```wgsl
@group(0) @binding(0) var<storage> foo: array<mat4x4f>;
@group(0) @binding(1) var<storage> bar: Stuff;

// ...
let numMatrices = arrayLength(&foo);
let numVerts = arrayLength(&bar.verts);
```

## 🔧 函数

WGSL 中的函数遵循以下模式：

```text
fn 函数名(参数) -> 返回类型 { ...函数体... }
```

```wgsl
fn add(a: f32, b: f32) -> f32 {
  return a + b;
}
```

## 🚪 入口点

WGSL 程序需要一个入口点，由以下属性之一标记：

- `@vertex` — 顶点着色器
- `@fragment` — 片段着色器
- `@compute` — 计算着色器

```wgsl
@vertex fn myFunc(a: f32, b: f32) -> @builtin(position) vec4f {
  return vec4f(0, 0, 0, 0);
}
```

### 着色器只使用其入口点访问的内容

```wgsl
@group(0) @binding(0) var<uniform> uni: vec4f;

fn foo() -> vec4f {
  return uni;
}

@vertex fn vs1() -> @builtin(position) vec4f {
  return vec4f(0);
}

@vertex fn vs2() -> @builtin(position) vec4f {
  return foo();
}
```

上面 `uni` 没有被 `vs1` 访问，因此如果在管线中使用 `vs1`，它不会显示为必需的绑定。`vs2` 通过调用 `foo` 间接引用了 `uni`，所以在管线中使用 `vs2` 时，它会显示为必需的绑定。

## 🏷️ 属性（attributes）

「属性（attributes）」在 WebGPU 中有双重含义：

1. **顶点属性（vertex attributes）** — 在顶点缓冲区相关文章中介绍
2. **WGSL 属性** — 以 `@` 开头

### `@location(number)`

`@location(number)` 用于定义着色器的输入和输出。

#### 顶点着色器输入

对于顶点着色器，输入由顶点着色器入口点函数的 `@location` 属性定义：

```wgsl
@vertex fn vs1(@location(0) foo: f32, @location(1) bar: vec4f) ...

struct Stuff {
  @location(0) foo: f32,
  @location(1) bar: vec4f,
};
@vertex fn vs2(s: Stuff) ...
```

`vs1` 和 `vs2` 定义了在地址 0 和 1 的输入，它们需要由顶点缓冲区提供。

#### Inter-stage 变量

对于 Inter-stage 变量，`@location` 属性定义了变量在着色器之间传递的位置：

```wgsl
struct VSOut {
  @builtin(position) pos: vec4f,
  @location(0) color: vec4f,
  @location(1) texcoords: vec2f,
};

struct FSIn {
  @location(1) uv: vec2f,
  @location(0) diffuse: vec4f,
};

@vertex fn foo(...) -> VSOut { ... }
@fragment fn bar(moo: FSIn) ...
```

上面的例子中：

- 顶点着色器 `foo` 将 `color` 作为 `location(0)` 上的 `vec4f`，`texcoords` 作为 `location(1)` 上的 `vec2f`
- 片段着色器 `bar` 将它们以 `uv` 和 `diffuse` 接收，因为位置是匹配的

#### 片段着色器输出

对于片段着色器，`@location` 指定了将结果存储在哪个 `GPURenderPassDescriptor.colorAttachments` 中：

```wgsl
struct FSOut {
  @location(0) albedo: vec4f,
  @location(1) normal: vec4f,
};
@fragment fn bar(...) -> FSOut { ... }
```

### `@builtin(name)`

`@builtin` 属性用于指定某个特定变量的值来自 WebGPU 的内置功能：

```wgsl
@vertex fn vs1(
  @builtin(vertex_index) foo: u32,
  @builtin(instance_index) bar: u32,
) ... {
  ...
}
```

上面例子中，`foo` 的值来自内置的 `vertex_index`，`bar` 的值来自内置的 `instance_index`。

也可以写在结构体中：

```wgsl
struct Foo {
  @builtin(vertex_index) vNdx: u32,
  @builtin(instance_index) iNdx: u32,
};
@vertex fn vs1(blap: Foo) ... {
  ...
}
```

在这个例子中，`blap.vNdx` 来自 `vertex_index`，`blap.iNdx` 来自 `instance_index`。

#### 内置变量一览

| 内部名称 | 阶段 | IO | 类型 | 描述 |
|----------|------|----|------|------|
| `vertex_index` | vertex | input | `u32` | 当前顶点在当前 API 级绘制命令中的索引，不依赖于绘制实例化。非索引绘制时，第一个顶点索引等于 `firstVertex`；索引绘制时，等于索引缓冲条目加上 `baseVertex`。 |
| `instance_index` | vertex | input | `u32` | 当前顶点在当前 API 级绘制命令中的实例索引。第一个实例索引等于 `firstInstance`，之后每个额外实例递增一。 |
| `position` | vertex | output | `vec4<f32>` | 当前顶点的输出位置（齐次坐标）。齐次归一化后处于 WebGPU 标准化设备坐标空间。 |
| `position` | fragment | input | `vec4<f32>` | 当前片段在帧缓冲空间的位置（`x, y, z` 已缩放，`w` 为 1）。 |
| `front_facing` | fragment | input | `bool` | 当前片段位于面向前方的图元上时为真，否则为假。 |
| `frag_depth` | fragment | output | `f32` | 视口深度范围内的片段更新后的深度。 |
| `local_invocation_id` | compute | input | `vec3<u32>` | 当前调用的局部调用 ID，即其在工作组网格中的位置。 |
| `local_invocation_index` | compute | input | `u32` | 当前调用的局部调用索引，即在工作组网格中的线性索引。 |
| `global_invocation_id` | compute | input | `vec3<u32>` | 当前调用的全局调用 ID，即其在计算着色器网格中的位置。 |
| `workgroup_id` | compute | input | `vec3<u32>` | 当前调用的工作组 ID，即该工作组在工作组网格中的位置。 |
| `num_workgroups` | compute | input | `vec3<u32>` | 通过 API 调度的计算着色器调度大小，即 `vec3<u32>(group_count_x, group_count_y, group_count_z)`。 |
| `sample_index` | fragment | input | `u32` | 当前片段的样本索引，范围为 `0` 到 `sampleCount - 1`。 |
| `sample_mask` | fragment | input | `u32` | 当前片段的样本覆盖率掩码，指示哪些样本被正在渲染的图元覆盖。 |
| `sample_mask` | fragment | output | `u32` | 控制当前片段样本覆盖率的掩码。写入值中的零位会导致颜色附件中相应样本被丢弃。 |

## 🎛️ 流程控制

像大多数计算机语言一样，WGSL 具有流程控制语句。

### `for`

```wgsl
for (var i = 0; i < 10; i++) { ... }
```

### `if`

```wgsl
if (i < 5) {
  ...
} else if (i > 7) {
  ...
} else {
  ...
}
```

### `while`

```wgsl
var j = 0;
while (j < 5) {
  ...
  j++;
}
```

### `loop`

```wgsl
var k = 0;
loop {
  k++;
  if (k >= 5) {
    break;
  }
}
```

### `break`

```wgsl
var k = 0;
loop {
  k++;
  if (k >= 5) {
    break;
  }
}
```

### `break if`

```wgsl
var k = 0;
loop {
  k++;
  break if (k >= 5);
}
```

### `continue`

```wgsl
for (var i = 0; i < 10; ++i) {
  if (i % 2 == 1) {
    continue;
  }
  ...
}
```

### `continuing`

```wgsl
for (var i = 0; i < 10; ++i) {
  if (i % 2 == 1) {
    continue;
  }
  ...

  continuing {
    // continue 会跳到这里
    ...
  }
}
```

### `discard`

```wgsl
if (v < 0.5) {
  discard;
}
```

使用 `discard` 会退出当前着色器。它只能在片段着色器中使用。

### `switch`

```wgsl
var a: i32;
let x: i32 = generateValue();
switch x {
  case 0: {        // 冒号是可选的
    a = 1;
  }
  default {        // 默认分支不需要出现在最后
    a = 2;
  }
  case 1, 2, {     // 可以使用多个选择值
    a = 3;
  }
  case 3, {        // 尾随逗号也是可选的
    a = 4;
  }
  case 4 {
    a = 5;
  }
}
```

`switch` 仅与 `u32` 和 `i32` 类型的变量工作，并且各分支的匹配值必须是常量。

## ⚡ 与其他语言的不同

1. `if`、`while`、`switch`、`break-if` 表达式**不需要括号**

```wgsl
if a < 5 {
  doTheThing();
}
```

2. **没有三元运算符**

许多语言有三元运算符 `condition ? trueExpression : falseExpression`，但 WGSL 没有。WGSL 有 `select`：

```wgsl
let a = select(falseExpression, trueExpression, condition);
```

3. **`++` 和 `--` 是语句，不是表达式**

许多语言有前置递增和后置递增运算符：

```js
// JavaScript
let a = 5;
let b = a++; // b = 5, a = 6（后置递增）
let c = ++a; // c = 7, a = 7（前置递增）
```

WGSL 没有这些。它只有递增和递减语句：

```wgsl
// WGSL
var a = 5;
a++;           // a 现在是 6
++a;           // 错误：没有前置递增这种东西
let b = a++;   // 错误：a++ 不是一个表达式，而是一个语句（语句不返回值）
```

4. **`+=`、`-=` 不是表达式，它们是赋值语句**

```js
// JavaScript
let a = 5;
a += 2;          // a = 7
let b = a += 2;  // a = 9, b = 9
```

```wgsl
// WGSL
var a = 5;
a += 2;          // a 是 7
let b = a += 2;  // 错误：a += 2 不是一个表达式
```

5. **调制（swizzles）不能出现在左边**

在某些语言中可以这样做，但在 WGSL 中不可以：

```wgsl
var color = vec4f(0.25, 0.5, 0.75, 1);
color.rgb = color.bgr;                 // 错误
color = vec4(color.bgr, color.a);      // 可以
```

> Note：有一个提议是增加这个功能。

6. **假装赋值给 `_`**

`_` 是一个特殊的变量，你可以赋值给它，来让某些东西看起来被使用了，但实际上并不使用它：

```wgsl
@group(0) @binding(0) var<uniform> uni1: vec4f;
@group(0) @binding(1) var<uniform> uni2: mat4x4f;

@vertex fn vs1() -> @builtin(position) vec4f {
  return vec4f(0);
}

@vertex fn vs2() -> @builtin(position) vec4f {
  _ = uni1;
  _ = uni2;
  return vec4f(0);
}
```

上面的例子中，无论是 `uni1` 还是 `uni2` 都没有被 `vs1` 访问到，因此如果在管线中使用 `vs1`，它们都不会作为必需的绑定出现。而 `vs2` 则引用了 `uni1` 和 `uni2`，所以当使用 `vs2` 在管线中时，它们都会作为必需的绑定出现。
