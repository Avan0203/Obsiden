
# WebGPU 基础

## 📌 getPreferredCanvasFormat

`navigator.gpu.getPreferredCanvasFormat()` 返回当前平台 canvas 交换链**最推荐**的像素格式字符串。

### 🎨 常见值

- `"bgra8unorm"` — Windows / macOS（D3D12、Metal 原生偏好）
- `"rgba8unorm"` — 部分 Linux / Android 平台

### 🔤 格式命名拆解（以 `bgra8unorm` 为例）

| 部分 | 含义 |
|---|---|
| `bgra` | 内存通道排列顺序：B → G → R → A |
| `8` | 每通道 8 bit |
| `unorm` | unsigned normalized，`[0,255]` → `[0.0, 1.0]` |

### ⚠️ 核心规则

> **configure 的 format 与 pipeline target 的 format 必须一致，否则 pipeline 创建直接报错。**

```js
const format = navigator.gpu.getPreferredCanvasFormat();

context.configure({ device, format });

const pipeline = device.createRenderPipeline({
    fragment: {
        targets: [{ format }],  // ⚡ 必须匹配
    },
});
```

### 🤔 为什么 WebGL 不需要查询？

| | WebGL | WebGPU |
|---|---|---|
| canvas 格式 | 固定 RGBA8，驱动隐式处理 | 显式暴露平台差异 |
| 设计哲学 | 浏览器替你决定 | **你自己决定，零隐式操作** |
| 性能可控性 | ❌ 驱动行为不透明 | ✅ 可预测、可优化 |

### 🔄 用非 preferred 格式会怎样？

- ✅ 颜色**不会错**（浏览器保证正确性）
- ❌ 每帧多一次 **格式转换 blit**，浪费 GPU 带宽
- ❌ Pipeline 是预编译不可变对象，浏览器**无法**替你重新编译

### 💡 重点总结

> 📍 `getPreferredCanvasFormat()` 不是为了颜色正确，而是为了 **零转换开销**。
> 📍 WebGPU 原则：**提供信息，不做隐式决定，选择权在开发者。**
